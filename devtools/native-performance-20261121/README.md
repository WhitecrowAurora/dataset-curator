# Native 并发性能修复（2026-11-21）

用户反馈：Torii 与 Qwen3-VL native 均慢，执行机为 RTX 4090、RTX 5090、V100，Q6，6 / 10 / 12 并发。本轮在 RTX 4070 Ti SUPER 16GB 上定位、实现并验证，没有连接这些执行机，也没有发布服务器变更。

## 已实现

- Qwen3-VL：原 CUDA Graph 判断错误地依赖配置上下文容量不超过 4096；24GB / 32GB 档默认 8192 / 16384，因此短描述也退回逐算子调度。现在按当前实际已用 KV 长度判断；不缩小用户上下文容量。超过 4096 走原 eager 路径，后续短请求可重新使用 Graph。运行时版本 `lulynx-qwen3vl-0.26`。
- Qwen Q6：Ada 的双缓冲量化矩阵路径从仅 4 / 8 行扩展至 4～16 行。保持 FP16 权重解量化及 FP32 累加顺序，未扩展到未经实测的 Blackwell 专用内核。
- Volta 兼容路径：批大小大于 8 时，合并相邻 8 块的解量化调用，每块 GEMM 仍维持原有 256 行形状和顺序。以 FFN 宽度 12288 为例，临时 FP16 权重缓冲由约 6 MiB 增至 48 MiB，不持久展开全模型。直接扩大 GEMM 的候选虽然更快，但出现数值差异，已舍弃。
- Torii：原 `generate_batch` 逐请求调用生成，且分流客户端与服务容量均固定为 1。现在使用官方 Qwen3.5 批量生成，保留左填充、图像顺序、`mm_token_type_ids`、独立 seed、重复惩罚、逐请求 token 上限、EOS 和完成原因。运行时版本 `lulynx-qwen35-0.3`。
- 托管 Torii native 分流自动并发为 2；用户指定并发会传到客户端，在服务内按最多 4 张处理，多余请求排队。日志显示在途数与实际批容量。复核默认仍为单请求；外部服务与 llama.cpp 路径不变。
- 延迟启动增加线程同步，避免并发首请求重复启动模型；空任务不加载模型。服务复用身份和运行指纹包含批容量。Torii 首轮 GPU 耗时使用 CUDA Event 计时。

## 实测

环境：Windows，RTX 4070 Ti SUPER / SM89 / 16GB，torch 2.13.0+cu132，transformers 5.14.1；优先 trainer python-flashattention 环境。桌面和游戏有背景负载（测试前约 1.8～1.9 GiB 显存、24%～38% GPU 利用率），结果是本机对照，不能作为其他显卡的绝对速度承诺。GPU 测试串行执行，没有停止其他应用。

### Qwen3-VL 8B Q6_K + 原配 F16 mmproj

原图像面积预算 589824、真实 NL 提示词、temperature 0.2、top_p 0.9、每请求独立固定 seed。完整描述预算 800，全部自然 EOS。下表为热运行；前后 token 序列完全一致。

| 场景 | 原耗时 | 修改后 | 说明 |
| --- | ---: | ---: | --- |
| 容量 8192，4 并发，完整 4 条描述 | 10.274 s | 5.909 s | Graph 修复，总耗时下降 42.5%；解码 8.236 → 3.858 s |
| 容量 16384，2 并发，完整 2 条描述 | 9.610 s | 4.817 s | Graph 修复，总耗时下降 49.9%；解码 8.639 → 3.810 s |
| 容量 3072，6 并发，完整 6 条描述 | 6.944 s | 6.869 s | 仅 Q6 路径改进；解码 4.063 → 3.923 s，整体收益很小 |

大容量测试因本机显存限制使用 4 / 2 并发，不能称为在 4090 / 5090 上验证了 6 / 10 / 12 并发。模型权重、像素预算和输出预算均未缩减来取得加速；试验的容量不同已单独列明。

64 token 性能探针（容量 1536，仅用于对照内核路径，不是产品预算）：

| 并发 | 原解码耗时 | 修改后 | 结果 |
| --- | ---: | ---: | --- |
| 6 | 1.196 s | 1.061 s | token 完全一致 |
| 10 | 1.292 s | 1.196 s | token 完全一致 |
| 12 | 1.334 s | 1.295 s | token 完全一致 |

矩阵测试覆盖 Q/K/V 分组、gate/up 分组、down、词表输出，batch 2 / 4 / 6 / 8 / 10 / 12 / 16，共 28 组比较均逐元素相同。Volta 兼容路径本机直接调用 10 / 12 行，10 组矩阵比较逐元素相同；大矩阵耗时约下降 18%～33%，小 K 投影基本持平或波动退化。不是 V100 本卡测试，也不是 V100 端到端速度。

大容量边界使用 2 层实际 decoder 验证：4096 Graph → 4097 / 4098 eager → 释放并复用短槽位；与全 eager 对照 logits 和 KV 长度一致。大模型完整描述与此边界专项分别验证，未把小模型测试冒充完整 8B 长文测试。

### ToriiGate-0.5 Q6_K + 原配 FP16 mmproj

本机自动选择展开 FP16 权重、官方 torch 线性注意力（环境没有 FLA）。面积预算 1,000,000、正式 caption 提示词、temperature 0.5、top_p 0.9、seed 20261119、JSON 生成预算 2048。

- 短请求固定预算 48 / 64：串行 9.140 s，2 张合批 5.353 s，输出 token 完全一致，耗时下降 41.4%。
- 完整两张图：串行 39.444 s，合批 16.834 s，重复合批 16.112 s。串行输出 399 token，合批 361 token，因此不能把耗时比直接说成纯计算加速倍数。
- 完整四张（两图各重复一次）：18.099 s，峰值 torch allocated 11.870 GiB；各自 seed 独立，同图同 seed 两份结果一致。
- 完整输出均自然 EOS 且可解析为 JSON。固定批次重跑逐 token 一致，但串行与合批两图中的一图措辞不同。官方浮点批计算存在舍入差异，随机采样会放大；未承诺跨批大小逐 token 一致，也未声称提高识别准确率。
- 调度器测试：不同 token 上限、短请求先结束、无效超长请求不拖垮有效请求通过。真实 worker 子进程收到 12 个并发 HTTP 请求，全部 200、预算及完成原因正确，服务公开 batch_size=4；测试后子进程已关闭。
- 密集对白测试仍可出现抄写一句可读对白、重复提及文字；这是已有模型遵循提示词的局限。本轮未宣称解决幻觉或小字精简质量，也未改变最终文本的 384 软目标 / 512 硬上限模块。

## 使用与限制

更新执行电脑客户端并重启 native 服务才能生效。Torii 建议先用 2～4 并发；6 / 10 / 12 请求会排队，不能认为数字越大越快。若需要维持单张计算路径，设为 1。Qwen 的 4090 / 5090 默认大容量短描述会满足新的 Graph 条件；V100 不支持此 Triton / Graph 路径。

Qwen 原有固定 KV 槽位仍按配置容量预分配，Graph 修复不减少这部分显存。根据本机 8B 配置（36 层、8 KV heads、head_dim 128、FP16），16384 容量的 6 / 10 / 12 槽位仅 KV 就分别占 13.5 / 22.5 / 27 GiB，尚未计入 Q6 权重、视觉模型、激活与临时缓冲。因此 5090 的默认 16384 容量加 10 / 12 并发会有严重显存压力；不能把高并发视为提速保证。常规打标先从 4096 容量、4 并发复测，确认提示词加生成预算可容纳再逐档增加；本轮未静默修改用户容量。

4090 / 5090 / V100 均待本卡复测；5090 没有得到经本卡验收的 Q6 专用内核。本次还没有 FLA 批处理、packed Torii 批处理、持续大数据集稳定性或准确率抽检结论。客户端最终文本预算、模型提示词、量化档位均未改。

原始 JSON / profile 留在本目录；临时测试脚手架在完成后归档到 trainer 的 `.delete`，未加入生产入口。没有 commit、push 或修改远端服务器。

最终回归：109 项通过（专项请求契约、并发延迟启动、客户端、CLI、服务槽位与 llama.cpp）；1 条现有 Starlette/httpx 弃用警告。Python 语法与 `git diff --check` 通过。第一次单独运行两个既有测试时，trainer 的嵌入环境未把本仓库加入 sys.path，收集失败；显式指定项目路径后回归全部通过，未改共享环境。
