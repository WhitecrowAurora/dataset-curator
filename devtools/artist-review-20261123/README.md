# 历史画师前缀核对与强制归并修复 · 2026-11-23

已部署服务器修复并生成客户端更新包。

## 实际原因

用户尚未点击强制按钮。只读检查服务器接收的 `shard-000004.tar` 历史产物，发现 33 个图片 / NL 条目的正文画师前缀与固定仓库表不同；元数据中的 artist 已是表中名字。例：图片 4140006 正文 `@otokoter`，表中 `ter_(otokoter)`。这可能包括旧别名或模型生成的名字差异，不凭前缀本身断言画师身份错误。

旧结果与冲突候选导致失败最初只是怀疑。该分片正式 package_artifacts 和 artifact_conflicts 均无记录；实际拦截在新回传记录的画师归并。最近历史回传任务未启用 reinject，随后普通归并拒绝这些前缀。不能仅凭截图确定对方当前运行的是哪个客户端包。

## 修复

- 历史强制模式同时规范新回传行、中心已有结果及冲突候选；沿用本次固定的画师表。完成后只归并一次，避免后续再次进入普通补注入而丢失强制选项。
- 普通补注入保留画师不一致的条目并返回图片 ID、原前缀、表中画师；格式不完整、无法确认正文边界时强制模式也仍返回详情。
- 中心异常报告经过历史 HTTP 路由和客户端 ApiError 保留，复用既有 history report 持久化和显示。中心错误文案区分“已回传但未登记”与本地“尚未回传”。
- 严格核对只用于显式历史补注入。普通归并保留已有 artist 元数据处理语义，额外 review 参数避免无关调用变化。
- 归并事务中有争议时回滚，不产生部分中心修改。原始接收文件不修改；补注入继续保留本地备份，不启动模型。
