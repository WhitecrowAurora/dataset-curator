# NL 提示词配置

这里的每个 `*.json` 就是一份 NL 提示词，**文件名（去掉 `.json`）就是新建任务页
下拉框里显示的名字**，中文、空格、括号都可以，不用改代码。

直接用文本编辑器改文件也行，页面上「编辑这个提示词」改的是同一份文件。

## 预置的那份

`默认提示词.json` 是内置提示词在**默认产出规格**下的快照，随安装包一起发出去，
当底稿或对照用。注意它是**静态文本**：tag 数量、字数区间都写死在文字里，不会跟
着页面上的「描述长度」「中文比例」变——那两个参数只作用于下拉框里的
「内置（按参数生成）」。想按参数变，就选「内置」；想改写，就从这份开始改。

## 字段

```json
{
  "prompt": "整段英文指令（必填）",
  "prompt_zh": "整段中文指令（可选，中文比例 > 0 时用）",
  "system": "system 那句话（可选，不写用内置的）",
  "note": "给自己看的说明（可选，不参与推理）"
}
```

- `prompt` 是**整段替换**内置提示词，不是追加。想改内置那份？页面里点
  「新建自定义提示词」，弹窗会先把内置内容填进来，在它上面改。
- `prompt_zh` 不写就代表"这批不出中文"——不会退回去用内置中文版，否则英文
  和中文两套指令各说各话，混在一批数据里分不清。
- 以 `_` 开头的键当作注释放行（`"_comment": "..."`），其余不认识的字段会报错。
- 改名不影响产物的"同源判定"：`provenance` 里记的是提示词文本的 sha256，
  只有改内容才会被当成换了一套指令。

## 注意

- 文件必须是 UTF-8 编码的合法 JSON。写坏了页面会把它列出来并标红，不会
  静默消失。
- 提示词里如果自己写了长度/数量要求，记得和页面上的「描述长度」「max_tokens」
  对得上——质检的合格线是另一套数，两边打架时会被判废再重打。
