# MONET 发色复核 · 三个包抽样实测

结论：链路可运行，但现有自动接受规则不适合直接用于混合素材包。120 张原图中 51 张自动接受、69 张转人工；已看图确认至少 18 张没有可见人类头发的图被自动接受，另有 8 张动物、玩偶、雕像被误用人类发色标签。不能把 42.5% 自动接受率称为准确率。

[打开逐图报告](index.html)：包含预览、各模型判断、实际级联执行阶段、独立 Qwen 审计、CAFormer 前三原生概率、颜色块和头发示意。可筛来源、抽样批次、结果和重点问题。

这是三个包内的抽样测试，没有全包跑完。每包在字节位置 0%、25%、50%、75% 读取各 16 MiB，分别固定随机种子抽 8 张完整 JPG；人物补样从 75%、88%、96% 窗口按 caption 筛候选，优先动漫描述，每包另取 8 张，与首轮不重复。共读取 336 MiB，避免下载三个大包。HTTP Range 的状态、起点、终点和长度均校验，tar header 通过 checksum 解析，抽中原图全量解码并记录 SHA256。

字节窗口抽样不等于全包均匀随机抽样，caption 筛人物也存在误报：补样中的 #119 是建筑图，#121 是鞋/裤子局部。源 caption 仅用于选样，不当发色真值。该库混有照片、商品、动物、风景；实际动漫人物样本很少，不能据此验收动漫相近发色准确率。

## 实际执行

使用现有 PixAI backend + 原型 HairModels + 原型 cascade.review；所有 PixAI 结果均为真实 GPU 推理，没有手工颜色冒充打标结果。PixAI BF16、batch=2，权重只加载一次后复用；两个 deepghs ONNX 走现有 CPU provider。Qwen 使用现有 llama.cpp、Qwen3VL-8B-abliterated Q6_K、F16 mmproj，串行 GPU 运行，测试后停止自己启动的服务。

| 批次 | MobileNet 提前接受 | CAFormer 接受 | Qwen 接受 | 转人工 |
| --- | ---: | ---: | ---: | ---: |
| 混合抽样 96 张 | 27 | 7 | 7 | 55 |
| 人物候选 24 张 | 8 | 2 | 0 | 14 |
| 额外头部裁图 2 次 | 1 | 0 | 0 | 1 |

为审计提前通过，两个分类器和 Qwen 也独立跑了所有样本；独立结果与实际级联 observation 分开存放，未把额外审计伪装成级联调用。120 张原图实际级联调用 Qwen 76 次；独立审计 120 次，0 次请求失败，Qwen 每张耗时中位约 1.78 秒。混合首轮 PixAI 平均约 250 ms/张（batch=2），不含约 10 秒首次加载。这是测试适配器复用 backend 的耗时，不能代表当前单图 Web 服务的连续吞吐。

## 看图核实的问题

- #4 鱼/珊瑚被接受为青发，#12 游艇被接受为黑发，#45 卧室被接受为黑发。共 18 张无可见头发的误通过见 [拼图](no-hair-accepted.jpg)。根因是 PixAI 全量分数里极低的发色概率仍被取为首选，遇到专用分类器同色就提前通过；两个专用模型本身没有“无头发”类。
- Qwen 也会把雕像、玩偶、动物当成有发色对象。#16 雕像金发、#42 绿色玩偶绿发、#46 长颈鹿棕发、#69 鹦鹉蓝发、#76 山羊白发均在 Qwen 阶段接受；所以仅改为“每张都过 Qwen”仍不够。
- #115 五人合照被 MobileNet 与 PixAI 同为黑发提前接受，PixAI 的多人判据没有触发；独立 Qwen 标出多人。人物补样还有 #110、#112、#124 类似情况。
- #106 是灰度铅笔画，专用模型接受黑发，Qwen 猜金发；图像本身不能确证原始发色，不能自动给具体色。
- #107 银灰发：PixAI grey，两个专用模型 light，Qwen silver，正确地留在人工。CAFormer 前三是浅色组 99.963%、红色约 0.009%、绿色约 0.007%；真正需要比较的 grey/silver 不在专用模型类别里。人工列表需要同时保留 PixAI/Qwen 的具体候选，不能给这些候选编造专用模型概率。

## 头部裁图对照

#101 三人动漫图：PixAI 棕发，专用模型蓝发，Qwen 蓝发且识别多人，转人工。手工裁出中央角色头部 #201 后，四者均 blue，级联提前接受蓝发。

#107 银灰发人物手工裁出头部 #202 后，仍为 grey / light / silver 分歧，转人工。裁图能减少角色/背景干扰，无法补齐模型没有的具体浅色类别。两例都是手工像素裁框，没有自动头部检测或头发像素分割。

建议下一步先在现有处理链内明确“人物可见头发”输入与按角色裁图，再校准自动接受条件；多人、灰度图及浅色细分类仍保留人工。当前只完成测试，没有修改线上接受策略或写入已有人工决定。
