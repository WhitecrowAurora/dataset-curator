## 后续实施：多进程、百万条处理与异常恢复

范围按用户确认：不增加项目 ID 或多项目决策隔离，继续使用现有分包命名。同输出目录已有有效结果仍默认跳过，只有强制重做才重新计算。

### 实现

- `tagger/storage/work.py`：输出目录下建立可重建的 SQLite 完成索引，事务领取图片；每个写者持有操作系统文件锁，活进程的慢任务不会因超时被抢。退出后再次领取先扫描已经发布的产物，再收回失效领取。
- JSONL/Parquet 使用包名（JSONL）、写者 UUID 与序号组成独立分片。先同步临时文件、原子发布，再登记完成；默认每 2000 行封盘，正常暂停/停止会刷新不足一片的缓冲。突然退出只在内存中的结果会重算。
- 其他进程占用的图片单独记 `busy`，不会标整个 HF 分片完成，网页显示“其他进程处理中”并保留续做记录。结束后仍有 busy 的任务需要再次继续。
- 决策改为 SQLite 事务；旧 `decisions.json` 首次迁入并保留原文件。冲突清单使用 SQLite 快照与分页，CLI 全量导出改成流式原子写入；网页每次最多返回 500 项。
- 合并记录、冲突候选、分发 ZIP 任务清单及缺失列表超过 8192 项后使用临时磁盘索引；排序和原有 seed 抽检结果保持一致。分包区间无重叠时采用二分查找。
- 续做参数使用原子写入、上一份有效 JSON 备份、每任务独立副本；任务开始时即保存。活跃任务排除于跨进程续做候选；未记住的 API 密钥和 HF token 不写入这些文件。
- 失败日志追加使用短文件锁。HF 同一缓存目录的消费/清理互斥，下载分片的临时状态也互斥；等待锁和退出预取响应停止。多个任务使用同一 HF 缓存时，消费阶段会排队；不同缓存可并行。

## 容量扩展：十亿总量、分包分批处理

用户确认的范围是整个数据集最多 10 亿张，先分批分包，再分批打标与合并；不把十亿张散图一次加载到单个本地任务。下面是新增容量边界支持，不能理解为已实测十亿张吞吐。

### 使用方法

1. 新数据集第一批在「数据打包 → 分包」把序号宽度设为 **10**，起始序号为 **1**。原有 6 位默认值保留，避免改变已有结果的 ID。
2. 第二批开始，填写紧接着的「上一批分包表」路径；程序继承宽度，并衔接图片序号和 `dist` 包编号。每批使用新的分包表文件名，保存好整条批次记录。分包分配按批串行完成；本功能不是多个分包调度器同时领取全局号段。
3. 成员按分发 ZIP 的 manifest 打标，沿用分配好的 ID。合并页「分包总表」可每行填一份表；既可逐批对账，也可选择多批一起对账。多表区间重叠时明确报错，避免把两批重复分配的序号算成一批。
4. 单批封包输入完整的本批原始素材；选择全局编号时，使用该批表内的 `seq_width` 与 `start_seq`。起点改变纳入封包指纹，默认起点 1 保留旧指纹。封包仍要求原素材集合、排序及画师规则与编号时一致；嵌套扫描、排除或任意子集不可只靠起点反推 manifest。

CLI 对应参数：`split --seq-width 10 --start 1`；续批 `split --previous-table <上一批表>`；多批合并 `merge --tables <表1> <表2>`；封包 `pack --seq-width 10 --start <本批起点>`。均扩展已有入口。

### 实现与已通过的专项验证

- 普通及嵌套分包接入起始序号、继承宽度及包编号；分包表原子写入并保存 `start_seq`、`seq_width`、`next_seq`。旧表无宽度时从端点推导，旧表的下一序号小于已分配端点时取端点上界加一。
- 嵌套分包过滤、坏图造成序号空洞时，下一批起点按本批预留序号上界计算；不再按成功张数回退。超过宽度容量在写包前报错。
- 合并支持多张显式分包表、去重相同表路径、识别跨批重叠；无画师名的纯数字 ID 也能参加区间对账。Python 整数、SQLite 64 位整数和浏览器数值类型均能精确表示 10 亿。
- 两批实际 ZIP 跨过 `999999999 → 1000000000`：图片编号连续，4 个包不重名；生产 `run_batch`、完成索引重开跳过、网页多表合并、JSONL 导出和 CLI 同链路通过。推理使用假后端，本轮不宣称模型性能验收。
- 5 万个区间、每包 2 万张，准确统计应交 **1000000000** 张；第 50000 个包之后继续编号通过。这是区间边界测试，没有创建十亿条结果。
- 嵌套分包使用带空洞扫描表并注入一张坏图，成功结果的 ID 和下一批起点正确；旧 6 位 ID 不变，9 位越界拒绝，跨批重复区间拒绝。
- 高位编号实际封包 3 张，再次运行正确跳过 3 张；HTTP 预览和任务提交保持 10 位 ID，上一批表缺失或格式错误返回可读错误。替换分包表失败时旧表字节不变。
- 浏览器连接工具在初始化时失败（缺少 sandboxPolicy），未完成浏览器点击验收；以正式 TypeScript/Vite 构建及 TestClient 访问首页、新 JS、预览和任务 API 验证接线。
