## 503 的证据和处理

- 旧日志确认：03:48:28 管理面板 `/api/summary` 返回 503，03:48:41 再次查询恢复 200。该路由在捕获访问本机 fox-label 的 `UpstreamError` 时返回 503，因此异常位于面板到调度 API 的调用链，不能归因浏览器网络。
- 排查首次直接调用 `/packages?limit=1` 耗时 5.595 秒，接近原 6 秒超时。随后只读数据库计时：读取 874 个包约 0.148 秒，统计约 0.005 秒，完整性分组约 0.003 秒。
- 跨一分钟的 8 轮观察全部返回 200，面板统计约 0.178～0.286 秒。没有持续慢查询或服务崩溃的证据。
- **旧失败未记录异常正文和上游路径，无法确认那一次是超时、连接错误还是上游错误响应。** 5.595 秒是当前排查发现的超时余量问题，不能作为历史异常根因的确证。未声称消除了所有 503。
- 已将包统计请求等待时间从 6 秒改为 15 秒；其他读接口保持原值。成功结果的缓存有效期从读取完成时计算，避免慢查询一完成缓存就过期。
