## 使用与生命周期

客户端「调度中心」→「持有分片与释放」，在实时执行区域下方。
当前包与预取包分别显示释放倒计时、上次成功回报时间及下次上报时间。
「停止并释放」先停止当前执行，再归还当前包和预取包、暂停接单；
「释放预取包」只归还预取包，当前执行继续。本地产物保留。
网络失败时显示释放未获中心确认，允许重试，不把未确认请求当成成功。

在线当前包和预取包默认有效期均为 172800 秒（48 小时）。成功握手、心跳、
托管 poll 或正常 ping 会续期；只读状态查询不续期，失败请求不推进成功回报时间。
已经到期的租约不能靠迟到心跳复活，也不能继续合并旧租约的上传正文。
后台每 30 秒检查到期租约，实际回收可能比倒计时归零晚一个检查周期。
离线派单保留独立的申报规则，不依赖在线心跳。

首次升级为现有在线租约提供完整 48 小时宽限，保留真实 last_beat_at；迁移只运行
一次，服务重启不反复延长。这意味着迁移宽限期间 expires_at 与旧 last_beat_at
之差可能超过 48 小时；后续成功回报才使两者之差重新成为 172800 秒。

## 本轮检查确认并修复的问题

检查范围包括本轮租约功能及前几轮的自动接单、断点恢复、画师注入、代理、
结果分享和本地核验链路。下列问题经过源码调用链和针对性场景确认；
没有把未能定位的用户截图直接归因到这些问题，也没有依据 dirty 状态判定引入时间。

| 问题 | 最终行为 |
| --- | --- |
| worker 异常退出后 finally 仍执行普通释放，恢复所需租约可能丢失 | 异常保留租约；正常返回和明确中断分别沿用对应收尾语义 |
| 停止超时后丢失仍存活的进程引用，可能误判已停止 | 保留活进程引用，主动释放必须确认执行进程已经退出 |
| 释放或到期后分项仍指定原设备，其他设备无法领取 | 清理该租约对应指定，保留其他分项及后来新租约的指定 |
| 逾期按领取时长判断，持续正常回报的包也被标红 | 按真正 expires_at 判断，已恢复正常的旧通知标为解决 |
| 旧任务 annotation 为 null 时，画师选项处理报错 | 统一转换为空选项；未知字段仍按原契约拒绝 |
| 结果核验只编辑 TAG 时，未检查有效 TAG 与保留 NL 的完整文本 | 所有编辑方式按完整文本检查，硬上限不超过 512 token |
| 重复导入记录时，后续记录的冲突候选可能丢失 | 合并全部候选；增加候选时重新进入待核验状态 |
| 旧租约到期后的 done 请求，可能在 finish 验证前先合并正文 | 合并层独立验证租约到期，避免旁路提交 |

同时修正释放期间身份切换、启动、领取队列等并发操作的状态冲突；
预取包已转为当前包时禁止按预取释放；幂等重放旧释放不清掉新的有效指定。
服务端状态缓存显示倒计时扣除缓存年龄，心跳失败不会虚构续期成功。

annotation:null 是单独确认的兼容缺陷，并不能证明先前用户的画师报错就是它。
另一次回归失败来自旧临时测试中代理函数替身只接受一个参数；适配测试替身后
通过，生产代理接口没有为旧替身回退，另用真实接口调用确认自定义代理参数。
