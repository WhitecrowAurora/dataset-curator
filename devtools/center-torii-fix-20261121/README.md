# 调度中心 ToriiGate 接入修复（2026-11-21）

调度中心的 NL 清单原先只包含 Qwen，且服务启动只走 Qwen3-VL profile；单独加下拉选项会导致未知模型或使用错误提示词。

现在模型下拉可选 ToriiGate-0.5。在线、被动托管、离线共用执行配置；选择时匹配 Q6_K 权重和 llama.cpp / native 引擎，保留服务别名，显式传递 Torii 提示词、JSON 解析方式与运行指纹。停止、取消、复用、异常退出继续使用已有全局服务生命周期。原 Qwen 路径保留，启动代码抽取成共用方法。

模型包沿用模型管理中的 Torii 路径。默认权重缺失时走已有固定 revision 下载，明确选了其他现存文件或不完整自定义目录时会提示检查，不静默换模型。当前固定验证 Q6_K + FP16 mmproj；native 自动 2、最多 4，llama.cpp 当前 1。CPU 和可见 CUDA 卡号透传到实际进程，CPU 同时关闭视觉编码器 GPU 卸载。

验证：
- 44 项专项：真实配置保存、prepare/start/snapshot/复用/停止流程（模型加载替身）、取消和加载失败、CPU/多卡设备命令、包路径、下载取消所有权、离线环境继承、上一版 Qwen gpu_mem 修复回归。
- 77 项客户端、描述、进度、服务槽位回归。
- 52 项现有 Web 服务、调度看门狗、Torii 提示词回归。
- TypeScript 检查和生产前端构建通过。独立 Edge 浏览器验证模型下拉、两种引擎、真实保存 API、刷新持久化、切回 Qwen、隐藏无效选项，零 JavaScript 错误。内置浏览器工具因 sandboxPolicy 连接错误不可用。
- 本机 RTX 4070 Ti SUPER、trainer Python/transformers 5.14.1，用实际 Q6 权重经中心 prepare 启动两种引擎，再由中心环境进入真实 CLI，使用别名 tagger。密集对话图均完成 JSON 解析并写出 NL 产物；训练 tokenizer 计数 native 205、llama.cpp 190，低于 384 软目标及 512 硬上限。另一张 6602 字节样本被既有小图规则跳过，未计为推理成功。两种服务最终均停止。此验证证明接入可运行，不代表大数据准确率或其他显卡性能验收；样本仍有过度复述小字的现象，本次未修改模型质量策略。

运行时磁盘剩余约 43GB / 9%，默认资源检查会因低于 15% 暂停。仅本次小样本命令使用 --no-guard，不改变用户日常配置，不删除用户文件。

更新客户端包并完全退出重启，在 调度中心 → 模型与执行 → NL 模型 选择 ToriiGate-0.5。无需改服务器。临时脚手架按要求归档至 trainer 的 .delete，生产源码不保留测试代码。
