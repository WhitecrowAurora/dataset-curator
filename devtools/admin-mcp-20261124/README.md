## 管理员使用

离线工单删除入口有两处：独立「离线工单」页面 → 展开「服务器已有离线工单」；工作区 →「结果与核验」→ 展开「已有离线任务：下载、取消或删除工单」。先点「删除工单」，再点「再次点击确认删除」。未完成的本工单占用会释放；其他分项、已经回传的结果和历史记录保留。清单归档至服务器 `state/.delete/offline/<工单ID>`。完全离线的成员不会实时收到撤销，管理员应先通知停止原任务。

网页顶部「AI 接口」打开 `/ai-access`，管理员创建独立密钥，选择仅查询或查询和操作，设置1～365天有效期。密钥只显示一次，服务器只存 SHA256 摘要，可以立即撤销。页面也提供桥接脚本与配置说明下载。

MCP 地址为 `http://119.28.16.93/mcp`，使用 `Authorization: Bearer <网页生成的独立密钥>`；JSON 模式的 Streamable HTTP，无常驻 SSE 或会话依赖。支持2025-06-18和2025-03-26。仅支持 stdio 的 AI 客户端使用 [配置说明](H:/tagger/mcp/center/README.md) 中的桥接方式，Python 3.10+，无需第三方依赖。

共有9个工具：总览、工作区、设备、分片、离线工单查询，以及预派单、设备启停/强制继续/并发调整/探测、离线工单生成、离线工单删除。只读密钥只暴露5个查询工具。操作通过既有管理员 API 执行，继续检查工作区、占用、租约、冲突和本机远程并发授权。设备命令 request_id 重试沿用，工单删除可重复提交；预派单和生成工单沿用原 API 的事务规则，不宣称所有写操作都支持网络重试去重。

操作记录保存在配置目录 `ai-access.sqlite3`，网页显示最近100次 AI 工具调用，不记录密钥正文和用户参数。未开放 SSH、shell 或任意服务器路径。
