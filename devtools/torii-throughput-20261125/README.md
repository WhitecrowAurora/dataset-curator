# Torii native 吞吐优化（2026-11-25）

本轮目标：保留 Q6 常驻权重、保持原图像与描述预算，降低 ToriiGate-0.5 的多请求延迟。实现与实测在本机 Windows / RTX 4070 Ti SUPER 16 GiB；未连接 5090、4090、V100 执行机，本性能任务未直接修改生产调度服务器；同一工作区另一个调度修复会话已同步接受 0～256 的服务端契约，见 devtools/center-issues-20261125/deploy.json。

## 实现

- Torii 使用逐请求状态的连续处理：完成即返回，空槽可接受新图片；CPU 图像预处理与 GPU 解码重叠。共享 Qwen3-VL 的调度器，混合注意力缓存由 Torii 独立模块负责。
- CUDA Graph 捕获词向量、32 层语言模型和输出投影。按当前上下文容量分桶，固定槽位、有限图数量、跨请求复用；预热恢复卷积/循环状态，防止预热推进真实请求。视觉/prefill 保持官方模型逻辑。
- 复用 Qwen3-VL Q6 投影、MLP 分组投影/SiLU 融合和批量采样。保留每请求 seed、重复惩罚、EOS、独立 token 上限，取消后完整替换槽位状态。
- 支持设备默认保留 GGUF 量化权重，不再因显存充足而持久展开整个 FP16 模型。Ampere+ 有 Triton 时使用融合量化算子；缺少 Triton 或旧 CUDA 卡使用已有 NVRTC Q6 路径。CPU 仍走原官方生成。视觉编码器和激活仍是 FP16，prefill 可以临时解量化单个矩阵；解码保持分块量化计算。
- 初始合批窗口由 10 ms 调整为 100 ms，满批立即执行；已有任务解码时不等待合批窗口。客户端先结算所有完成结果、统一让步，再补发空槽，避免同批逐张重复休眠。
- Torii native 的配置、服务与实际槽位容量统一为 1～256；调度页和新建任务分流页提供滑动条及右侧数字输入框，保留 0 自动（实际默认 2）。并发探测仍使用有限样本逐档测试，不自动尝试 256。CUDA worker CPU 线程最多 8，避免高核心数机器调度开销。现有占空比/温控设置继续有效；需要全速时使用已有界面的 100% 占空比。
- 运行时版本 `lulynx-qwen35-0.6`。FP8 新量化功能不在本轮实现中。

## 数值与正确性

- `validation.json` 固定相同输入 token 的 64 步全词表 logits：动态缓存与新静态槽位路径最大误差 0.03125、RMSE 0.002487、PSNR 84.046 dB，64 步各行 argmax 一致。PSNR 定义为 `20*log10(max(abs(reference))/RMSE)`，不是图像重建 PSNR，也不是原 BF16 对 Q6 的量化精度评价。
- 旧路径与新路径完整随机描述可能不同。缓存注意力长度分桶、融合计算与采样产生微小数值差异，不能承诺逐 token 等价；同一新路径 Graph 开/关完整输出相同。未建立全库人工质量集，未宣称准确率提升。
- MLP 1/2/4/8 行、3 个层的随机输入对照均逐元素相同。单算子微基准有背景波动，仅以完整模型结果判断收益。
- 8/40/16/32 token 的混批，短请求在其他请求未完成时补入，8 请求全部完成；重复图片的短输出逐 token 相同。取消 1/3 槽后重新加入，4 请求正常完成。
- 真实 HTTP 两轮各 12 请求全部 200，重复输出相同；错误模型/过长上下文/正常请求并发返回 400/400/200，健康、版本、模型接口正常，关闭无残留服务线程。完整描述 303 token、自然 EOS、合法 JSON。
- 实际 TaggerClient → HTTP → 模型 → 质量检查 → 原子落盘：4 图 13.314 s，4 成功、0 失败；再次运行全部跳过。最终训练文本实际 tokenizer 长度为 239/455/268/475，均符合 512 硬上限，384 仍是软目标。
- CPU/调度/采样/暂停续做/产物等 87 项通过，trainer 环境因无 pyarrow 跳过的 Web 模块另用项目 env 跑 19 项全部通过，共 106 项。TypeScript/Vite 构建成功，保留已有大 chunk 提示；后续容量扩展另通过 36 项配置/服务/兼容性测试与 21 项客户端回归，范围含重叠；独立 Edge 浏览器验证滑块、输入框双向同步、1/256 边界、自动值、禁用与刷新保留，未更改用户真实配置。

## 使用

关闭客户端与 native 模型进程后，用 `dist/tagger-20261125-torii-throughput-patch.zip` 覆盖原目录；新安装使用 `dist/tagger-20261125-torii-throughput.zip`。补丁含本轮及之前累计客户端修复、最新前端和 ASCII 启动脚本，不覆盖个人 configs、模型、任务和产物。

选择 native + ToriiGate-0.5 + Q6；依赖管理中的“Torii native CUDA 加速（可选）”组提供 FLA/Triton，4070/4090/5090 建议安装该组才能获得这里的加速路径。先从 4 并发开始，再探测 6/8；这台 16 GiB 卡 8 路先前 torch 峰值约 10 GiB，HTTP 连续运行整卡采样峰值约 13.2 GiB，混合 TAG 工作还需给分类模型留空间。当前用户 env 未自动安装此依赖组，不会假装安装完成。

SHA256、ZIP CRC、当前源码匹配、私密配置排除见 `package.json`。完整日志/JSON 保留本目录与 E:\tagger-validation\torii-throughput-20261125。临时测试脚本归档至 H:\lulynx-trainer\.delete\tagger-torii-throughput-20261125\backend\smoke\tagger-torii-throughput-20261125，产品不包含实验脚本。修改前快照在 H:\tagger\.delete\torii-throughput-20261125\before。

本会话工具目录没有 jcodemunch_guide，使用直接源码和实际执行记录。没有 Git reset/stash/drop/push，本性能任务没有直接部署服务器；并行调度修复的部署记录单独保留。


## 256 并发补充验证

- `large-batch.json`：真实 Q6 权重，32/64/256 行 MLP 融合投影和词向量 CUDA Graph 均通过；与原 16 行分块参考最大误差为 0，捕获重放逐元素一致。256 行该 MLP 测试额外峰值约 19.94 MiB，不是整个模型 256 槽的显存。
- Torii 解码显式使用分块量化 MMA，避免 >=32 行时走预填充的临时整矩阵反量化。Qwen3VL 默认策略保持原样。词向量单 token 解码避开动态 `unique`，支持大批量图捕获。
- `buckets.json`：831/2016 token 的混合输入，跨 2048→4096 上下文桶、取消后复用，Graph 开/关及复用结果相同。
- 256 槽完整模型未在本机 16 GiB 卡验证；KV 与混合循环缓存按槽位占用显存，设置可保存不等于硬件能承载。产品本机 llama.cpp 路径仍为 1 槽，这次放开的是 native。
- 控件验证截图 `concurrency-ui.png`，报告 `ui-test.json`；测试宿主使用真实 ExecutionSettings 组件和内存模型清单，不连接或修改真实调度账号。


## llama.cpp 对照与交付快照

详见 `llamacpp-comparison.md`。同参数 8 路 native 约 31 图/分钟、llama.cpp 约 25.5；llama.cpp 默认采样约 33，二者接近，不能宣称 native 全面更快。单路 llama.cpp 更快，显存也更低。

最终发行基于本轮已验证的 22:44 源码/UI 快照，叠加最后的 MLP CPU 兼容修正。另一会话随后开发的 benchmark 面板未混入本包；工作区保留其全部代码。完整快照来源与 SHA256 见 package.json。
