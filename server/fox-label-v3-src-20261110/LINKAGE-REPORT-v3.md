# v3 联动审计报告（4 轮）

对象：`worker.py`（客户端，507 行）↔ `server.py` + `dispatch.py`（服务端，v3 调度）
方法：契约静态比对 → 真机链路 → 异常与恢复 → 舰队长跑
结论：**4 轮全部通过**，共发现并修复 **9 个缺陷**（2 个事故级），累计 9 套 314 项测试全绿。

## 第 1 轮：接口契约审计（静态比对）

逐个端点比对客户端调用与服务端契约：字段名 / 状态码 / 语义 / 时序。

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| C1 | `worker.py show` 用 `POST /hearbeart {leases:[]}` 查状态 | **每敲一次 `show` 就顺手领走一个包**（服务端 `assign()` 有副作用），没人处理，直到 TTL 到期；池子被悄悄吃掉 | 新增只读端点 `POST /api/v1/status`（secret 鉴权、不派工不续约），`show` 改用它 |
| C2 | 心跳只续 `active`，`prelock` 从不续约 | 干活动辄数小时，预锁 TTL 240s 必然过期 → "预锁缓冲"完全失效，`done` 后只能重新派一片 | 心跳携带**手上全部租约**；只有 `active` 被收回才停手，预锁被收回只告警 |
| C3 | `api()` 把 503 当致命错误 | 服务端存储短暂不可用（我们设计为"请重试"）会让客户端直接失败退出 | 502/503/504 纳入重试（退避），仍失败才报错 |
| C4 | `run_task()` 里 `Path(args.out)` | 不给 `--out` 时 `args.out is None` → `TypeError` 崩栈 | 由 `do_one` 把 `out_dir` 传下去 |
| C5 | 连续心跳失败时无自救 | 服务端被重置/设备被删后，客户端仍闷头干几小时，最后提交被拒，全部白费 | 连续失败 5 次做一次只读 `status` 核对；租约确实没了才停，网络不通则继续干 |

## 第 2 轮：真机链路

真实服务端 + 真实 HTTP + 假打标任务，跑完整循环：

```
login（签发 secret / 生成 device_id）→ handshake 派工 → 下载校验
   → 打标（--cmd）→ 心跳续约 → done → prelock 升 active → 下一片
```

发现：

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| C6 | `--once` 收工后不归还新派到的租约 | 服务端在 `done` 时已自动补派，客户端却退出，该片闲置到 TTL（默认 360s）才回池；30 台设备频繁重启时浪费明显 | 新增 `POST /api/v1/release`（**不算失败**、不触发冷却、包立刻回池），客户端在 `--once` / Ctrl-C / 异常退出时归还 |
| C7 | 重复归还同一租约 | 第二轮归还返回 409，日志里出现无意义告警 | 归还做幂等：已归还的记入集合跳过，409 视为成功 |

| 场景 | 结果 |
|---|---|
| 预锁被服务端收回 | ✅ 当前作业继续跑完并成功提交，日志提示"预锁丢失，做完再要新的" |

| 客户端 `kill -9` 后重跑 | ✅ 服务端租约仍在（未被误释放），重跑可继续拿到活 |
| `secret` 被重置 | ✅ 心跳立即识别 401 → 停手 → 退出码 3，不会白干 |

发现：

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| C8 | 管理员"打回"出来的包在 v3 下是**死包** | `reopen --to claimed` 保留原认领人但不建租约：v3 调度不认（只派 available）、v2 也抢不到 → 包包永久卡住，谁也没法交 | v3 调度把"claimed 且无 open 租约"的包重新纳入派工池（派工时就地改认领人）；同时保留 v2 打回语义不变 |
| C9 | 缺体检手段 | 死包/孤儿租约/幽灵租约只能靠人肉翻库 | 新增 `server.py doctor [--fix]`：列出三类异常并可一键回池 |

## 修复后的完整契约（客户端视角）

| 端点 | 用途 | 幂等 | 副作用 |
|---|---|---|---|
| `POST /api/v1/handshake` | 登记设备、领派工 | 是 | 派 active（+ 配额允许时 prelock） |
| `POST /api/v1/heartbeat` | 续约 + 报进度 + 领下一片 | 是 | 续约、回收超时、补派 |
| `POST /api/v1/status` | 只读查自己 | 是 | **无**（`show` 用这个） |
| `POST /api/v1/done` | 交付 | 否（重复 → 409） | 包转已完成、补派 |
| `POST /api/v1/fail` | 上报失败 | 否（重复 → 409） | 包回池、触发失败冷却 |
| `POST /api/v1/release` | 归还（收工/中断） | 是（重复 → 409 且静默） | 包立刻回池、**不**计失败 |

客户端退出码：`0` 正常/池子空 · `2` 用法 · `3` 认证失效 · `4` 下载校验失败 · `5` 租约失效 · `6` 任务失败。

## 遗留

1. **产物回传**仍未闭环：`done` 只做状态流转，`artifacts-*.jsonl` 依旧靠交回目录。
2. **客户端无"长驻等待"模式**：池子空了就退出（`0`）。无人值守需要 `--wait` 轮询。
3. **同 device_id 双开**：两台机器用同一份配置会互相顶替续约，当前无检测无告警。
4. **`doctor` 尚未纳入定时任务**：建议在总机 crontab 每日跑一次 `doctor`。
