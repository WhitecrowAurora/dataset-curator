# 休眠计时与分片释放确认 · 2026-11-23

本轮确认并修复 `tagger/guard.py` 占空比计时缺陷，客户端分片释放增加两步确认。没有修改默认占空比、温度阈值、服务器租约或本地产物保留规则。

## 已确认的问题

旧代码在主动 sleep 之前保存时间边界，因此下一轮把上次 sleep 一起计入 busy。可控时钟复现：每轮实际工作 7 秒，占空比 0.7，连续六轮休眠为 3、4.286、4.837、5.073、5.174、5.217 秒。修复后每轮稳定工作 7 秒、休眠 3 秒。

边界从实际休眠结束重新计时，操作系统额外休眠也不计入下一轮。检查调用链还发现 `JobManager` 多卡分包的 `_lane` 共用 ResourceGuard，因此时间边界改为 threading.local，每个执行线程独立结算，共用原温控策略。返回当前线程本次结算结果，避免返回被其它线程覆盖的 last_report。

截图中的“提速 40%～80%”没有真实模型或 GPU 基准支持。在不触及休眠上限、固定处理时长、单执行流、无其它空闲的简化模型中，旧占空比 0.7 稳态相当于约 0.571，本次修正理论吞吐提高约 22.5%。这不是实际打标测速；多并发期间已有请求会继续运行，不能由此推导显卡利用率或保证实际提速。仅凭截图中的 60°C 不调整所有用户的默认 duty_cycle。

## 释放确认

`LeasePanel.tsx` 的当前包和预取包释放都先展开确认提示，显示仓库和包名、暂停接单／归还预取包／本地产物保留等影响。点击明确的确认按钮才调用原释放 API，可随时取消。首击按钮在提示打开期间禁用，快速连点不会直接提交。正常轮询保留同一租约确认；分片 ID、类型、仓库或包名变化、断连或操作锁定会清除旧确认。
